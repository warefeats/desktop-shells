# Windows passes run in a logged-in interactive session reached through a scheduled task

Commands over ssh to the Windows rig land in session 0, which has no desktop, and neither WebView2 nor Electron will create a usable window there. The web-map-renderers runner avoided this with headless Chromium and recorded in its ADR 0002 that launching into the interactive session through the Task Scheduler works but is not something a reader without a monitor can rerun. Desktop shells have no headless mode, so this runner takes that path: the rig's user account is auto-logged-on, the desktop stays unlocked for the duration of a run, and ssh registers and starts a scheduled task that runs interactively in that session and writes results to disk for scp. The cost is a rig whose desktop is unlocked during runs and a reproduction step a reader needs a monitor or autologon to repeat; both are named on the page. Running the Windows leg by hand at the box was rejected because it cannot be scripted, and a resident polling agent was rejected as one more moving part to document.

Consequence found on the first run: a window created from a scheduled task in that session is judged occluded by Chromium's native window occlusion tracker, and Electron then never delivers an animation frame, while WebView2 does. Both shells are launched with `--disable-features=CalculateNativeWinOcclusion`, Electron through argv and WebView2 through `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`, so the treatment is identical; the run file's protocol names the switch.
