# Memory is attributed by responsible coalition on macOS and by process tree on Windows

Summing resident set size over a shell's child processes undercounts the Tauri candidate on macOS, because WKWebView's content and networking helpers are spawned by the system and are not children of the app; the author's earlier geobench report measured that way and had to disclaim the row. This runner reads physical footprint for the process coalition the app is responsible for, via the system `footprint` tool, which captures those helpers; on Windows, WebView2 processes are children of the host, so a parent-PID walk over private working set is sufficient. The two figures are not the same statistic, so the page never compares memory across rigs, only across candidates on one rig, and the rule is written into every run file. Reporting a plain tree sum with the gap named was rejected because the gap is the whole Tauri memory story on macOS.
